WooCommerce Product Filter Setup Guide

Why Default Filters Might Not Be Enough

WooCommerce comes out of the box with core filter widgets and blocks: filter by price, attribute, and rating. While these work fine for basic store setups, growing stores face three major challenges with native filtering:

  • Full Page Reloads: Standard widgets refresh the entire page upon selection, disrupting the buyer's flow.
  • Complex Taxonomies: Native filters often struggle when combining multiple custom taxonomies or meta keys simultaneously.
  • Performance Bottlenecks: Unoptimized database queries on large product catalogs (10,000+ SKUs) can slow your store down dramatically.

To solve this, we can take control using custom hooks, dynamic AJAX queries, and clean frontend UI tweaks.

Step 1: Setting Up Product Attributes Correctly

Before writing code or installing plugins, your store's data structure must be organized. Filters rely on standard attributes rather than custom field tags whenever possible because WooCommerce indexes attributes efficiently.

  1. Navigate to Products > Attributes in your WordPress dashboard.
  2. Create global attributes (e.g., "Color", "Size", "Material"). Ensure "Enable Archives?" is checked.
  3. Assign these attributes to individual products or global variable product variations.

Once your attributes are neatly organized, you can filter against them smoothly via native routines or custom PHP functions.

Step 2: Building Dynamic Filters via PHP (The Custom Approach)

When my clients in Rajkot need custom filtering logic—like filtering products by custom ACF fields, dynamic price sliders, or specific brand taxonomies—I hooks into WooCommerce's main product query using the woocommerce_product_query action hook.

Here is a practical PHP snippet you can place inside your child theme's functions.php file or a custom site plugin to alter the product query based on URL parameters:

/**
 * Custom WooCommerce Product Filtering Logic
 * Author: Shiv Parmar
 */
add_action( 'woocommerce_product_query', 'sp_custom_product_filter_query' );

function sp_custom_product_filter_query( $q ) {
    // Ensure we are modifying the main query on product archives
    if ( ! is_admin() && $q->is_main_query() && ( is_shop() || is_product_taxonomy() ) ) {

        // Check for dynamic 'in_stock' filter parameter
        if ( isset( $_GET['filter_stock'] ) && 'instock' === $_GET['filter_stock'] ) {
            $meta_query = $q->get( 'meta_query' );
            $meta_query[] = array(
                'key'     => '_stock_status',
                'value'   => 'instock',
                'compare' => '='
            );
            $q->set( 'meta_query', $meta_query );
        }

        // Check for custom taxonomy filter (e.g., Brand)
        if ( ! empty( $_GET['filter_brand'] ) ) {
            $tax_query = $q->get( 'tax_query' );
            $tax_query[] = array(
                'taxonomy' => 'product_brand',
                'field'    => 'slug',
                'terms'    => sanitize_text_field( $_GET['filter_brand'] ),
                'operator' => 'IN',
            );
            $q->set( 'tax_query', $tax_query );
        }
    }
}

Step 3: Elevating UX with Fast AJAX Filtering

Nobody likes page reloads. Implementing an AJAX-based reload keeps customers engaged and speeds up browsing. Here is a simple JavaScript example using Native Fetch API to intercept filter form submissions and update the product container dynamically:

/**
 * Frontend AJAX Handling for WooCommerce Filters
 * Developer: Shiv Parmar
 */
document.addEventListener('DOMContentLoaded', function () {
    const filterForm = document.querySelector('#sp-product-filter-form');
    const productContainer = document.querySelector('ul.products');

    if (filterForm && productContainer) {
        filterForm.addEventListener('change', function (e) {
            e.preventDefault();

            const formData = new FormData(filterForm);
            const searchParams = new URLSearchParams(formData).toString();
            const currentUrl = window.location.pathname + '?' + searchParams;

            // Update browser URL without reloading
            history.pushState(null, '', currentUrl);

            // Add loading class to product container
            productContainer.classList.add('loading-fade');

            fetch(currentUrl)
                .then(response => response.text())
                .then(html => {
                    const parser = new DOMParser();
                    const doc = parser.parseFromString(html, 'text/html');
                    const newProducts = doc.querySelector('ul.products');

                    if (newProducts) {
                        productContainer.innerHTML = newProducts.innerHTML;
                    } else {
                        productContainer.innerHTML = '<p class="woocommerce-info">No products found matching your selection.</p>';
                    }
                    productContainer.classList.remove('loading-fade');
                })
                .catch(error => {
                    console.error('Filter Error:', error);
                    productContainer.classList.remove('loading-fade');
                });
        });
    }
});

Combine this script with a quick CSS rule for seamless visual transition feedback:

/* Smooth transition during AJAX loading */
ul.products.loading-fade {
    opacity: 0.4;
    pointer-events: none;
    transition: opacity 0.3s ease-in-out;
}

Step 4: Off-the-Shelf Plugin Alternatives

While custom code is excellent for unique features, you don't always need to reinvent the wheel. When client project timelines are tight, I frequently recommend and implement these tested WooCommerce filtering plugins:

  • HUSKY – Products Filter for WooCommerce: Extremely customizable, supports AJAX, taxonomy, and meta queries seamlessly.
  • YITH WooCommerce Ajax Product Filter: Excellent preset designs out of the box, offering clean UI controls for colors, images, and dropdowns.
  • Filter Everything: One of my top choices for heavy WooCommerce setups due to its clean URL structure and strong SEO-friendly indexing features.

Step 5: Crucial Performance Optimization Tips

Adding dynamic filters adds complexity to MySQL queries. If you notice high server response times after enabling multi-attribute filtering, apply these performance tweaks immediately:

  1. Enable WooCommerce Lookup Tables: Go to WooCommerce > Status > Tools and run "Regenerate product attribute lookup tables". This turns complex relational queries into direct table lookups.
  2. Cache Transient Queries: For custom filtering queries that don't change by the minute, store the output using WordPress Transients API.
  3. Limit Multi-Select Depth: Avoid allowing deeply nested, unlimited multi-select taxonomy combinations unless absolutely necessary. Every extra taxonomy join increases SQL execution time exponentially.
