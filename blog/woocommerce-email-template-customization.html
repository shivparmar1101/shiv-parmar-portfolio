Understanding the WooCommerce Email Architecture

Before jumping into code, it is essential to understand how WooCommerce handles email templates under the hood. WooCommerce provides a core set of email template files located in the plugin directory under woocommerce/templates/emails/.

There are two primary ways developers customize these emails:

  1. Template Overrides: Copying the template files from the WooCommerce plugin directory to your active child theme directory and altering the HTML structure directly.
  2. Action and Filter Hooks: Programmatically injecting content or modifying styles without editing the underlying template files.

As a rule of thumb in my client projects here in Rajkot, I always prefer using hooks and filters first. Overriding actual template files should be reserved for scenarios where structural changes cannot be achieved through hooks alone. Minimizing file overrides ensures easier updates when WooCommerce updates core template versions in the future.

Method 1: Customizing Emails Using PHP Action Hooks

WooCommerce email templates are packed with action hooks. These hooks allow you to insert custom messaging, dynamic discount codes, or helpful resources right into the email body without breaking template inheritance.

Here is an example where I add a custom notification box specifically to the "Customer Processing Order" email template using the woocommerce_email_before_order_table hook.

/**
 * Add a custom notice box before the order table in customer processing emails.
 * Developer: Shiv Parmar
 */
add_action( 'woocommerce_email_before_order_table', 'shiv_add_processing_email_custom_notice', 20, 4 );

function shiv_add_processing_email_custom_notice( $order, $sent_to_admin, $plain_text, $email ) {
    // Target only the customer processing order email
    if ( 'customer_processing_order' === $email->id ) {
        echo '<div style="background-color: #e8f5e9; border-left: 4px solid #2e7d32; padding: 15px; margin-bottom: 20px;">';
        echo '<h3 style="margin: 0 0 8px 0; color: #2e7d32;">We are preparing your order!</h3>';
        echo '<p style="margin: 0; color: #333333;">Thank you for shopping with us. Our fulfillment team in our warehouse is currently packing your order with care. You will receive another notification once it ships.</p>';
        echo '</div>';
    }
}

Place this code inside your child theme's functions.php file or a custom functionality plugin. Notice how we inspect $email->id to target specific email types so we do not accidentally print this message on admin notifications or refunded order emails.

Method 2: Applying Custom Inline CSS via Filters

Email clients (especially Microsoft Outlook and Gmail) are notoriously strict regarding CSS support. Modern CSS like Flexbox and CSS Grid rarely work consistently. WooCommerce addresses this by passing CSS through an inline-styler class before sending out the email.

To inject custom styles into all WooCommerce emails safely, we can leverage the woocommerce_email_styles filter hook.

/**
 * Add custom inline styles to WooCommerce transactional emails.
 * Author: Shiv Parmar (Rajkot, IN)
 */
add_filter( 'woocommerce_email_styles', 'shiv_custom_woocommerce_email_styles', 10, 2 );

function shiv_custom_woocommerce_email_styles( $css, $email ) {
    $css .= "
        #header_wrapper {
            background-color: #1a252f !important;
            padding: 36px 48px !important;
            border-bottom: 4px solid #e74c3c;
        }
        #header_wrapper h1 {
            font-family: 'Helvetica Neue', Helvetica, Roboto, Arial, sans-serif !important;
            font-size: 26px !important;
            color: #ffffff !important;
        }
        .td {
            font-family: 'Helvetica Neue', Helvetica, Roboto, Arial, sans-serif !important;
            color: #444444 !important;
        }
        .order_details {
            border: 1px solid #e0e0e0 !important;
        }
    ";

    return $css;
}

Using this filter guarantees that your custom styles are automatically converted into inline styles attributes on every HTML element prior to dispatching the mail payload.

Key Insight: Never rely on external stylesheets or <style> tags alone for transactional emails. Email rendering engines vary dramatically across clients; inlining your CSS guarantees structural and visual consistency across desktop, mobile, and webmail clients alike.

Method 3: Template Overrides for Structural Changes

When hooks and CSS filters are not sufficient to reach your design requirements, you can override WooCommerce templates directly. Here is the correct, safe workflow to follow:

Step-by-Step Template Override Process

  1. Navigate to wp-content/plugins/woocommerce/templates/emails/.
  2. Locate the specific file you want to edit (for example, customer-processing-order.php).
  3. Copy that file into your active child theme directory inside a subfolder named woocommerce/emails/. The complete path should look like this: wp-content/themes/your-child-theme/woocommerce/emails/customer-processing-order.php.
  4. Modify the copied PHP file in your theme directory as needed.

For example, if you wish to display custom order metadata—such as a VAT number or delivery instructions collected during checkout—you can directly retrieve it from the order object inside your custom template file:

// Example snippet inside child-theme/woocommerce/emails/email-order-details.php

$delivery_notes = $order->get_meta( '_delivery_notes', true );

if ( ! empty( $delivery_notes ) ) {
    echo '<div style="margin-top: 15px; padding: 10px; border: 1px dashed #cccccc;">';
    echo '<strong style="color: #555555;">Delivery Instructions:</strong> ';
    echo esc_html( $delivery_notes );
    echo '</div>';
}

Method 4: Programmatically Displaying Custom Field Meta Data

Instead of modifying physical files to display custom order fields, WooCommerce provides an incredibly convenient array filter named woocommerce_email_order_meta_fields. This is my preferred approach when building store solutions for clients.

/**
 * Append custom meta fields directly into order meta section in emails.
 */
add_filter( 'woocommerce_email_order_meta_fields', 'shiv_add_custom_checkout_meta_to_emails', 10, 3 );

function shiv_add_custom_checkout_meta_to_emails( $fields, $sent_to_admin, $order ) {
    $gst_number = $order->get_meta( '_customer_gst_number', true );

    if ( $gst_number ) {
        $fields['gst_number'] = array(
            'label' => __( 'GST Identification Number', 'text-domain' ),
            'value' => esc_html( $gst_number ),
        );
    }

    return $fields;
}

This code automatically inserts formatted details directly into the existing order table within the email without breaking structure or requiring template maintenance during core plugin updates.

Testing Your Custom Email Templates

Development without rigorous testing usually leads to broken layouts in production. When testing emails locally or on staging servers, I recommend the following toolkit:

  • WP Mail Logging: A plugin that captures every email outgoing from WordPress so you can inspect the exact raw HTML content output.
  • Mailtrap or WP Offload SES: SMTP trapping tools that catch outgoing mails in a simulated inbox without emailing actual end customers.
  • Litmus or Email on Acid: Tools to preview how your customized template renders across Outlook, Apple Mail, Gmail, and mobile operating systems.
