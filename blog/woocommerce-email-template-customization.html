Understanding the WooCommerce Email Architecture

Before jumping into code, it is important to understand how WooCommerce structures its email engine. WooCommerce handles emails through a collection of template files located inside the core plugin directory: woocommerce/templates/emails/.

These templates handle everything from the global structural markup (email-header.php and email-footer.php) to specific notification layouts like customer-processing-order.php or admin-new-order.php.

When customizing these emails, developers generally have three main approaches:

  • Global CSS Styling via Hooks: Quick visual tweaks without touching core template files.
  • Action Hooks and Filters: Injecting custom dynamic content into existing templates safely.
  • Template File Overrides: Full structural layout control by copying files into your child theme.

Method 1: Customizing Email Styles via PHP Hooks

If you simply want to alter colors, typography, border-radii, or container padding across all emails, overriding template files is overkill. WooCommerce provides the woocommerce_email_styles filter hook, allowing you to inject custom inline CSS directly into the compiled email HTML.

Add the following code snippet to your child theme's functions.php file or via a custom functionality plugin:

/**
 * Inject custom inline CSS into WooCommerce emails
 * Author: Shiv Parmar
 */
add_filter( 'woocommerce_email_styles', 'shiv_custom_woocommerce_email_styles', 10, 2 );
function shiv_custom_woocommerce_email_styles( $css, $email ) {
    $custom_css = '
        #header_wrapper {
            background-color: #1e293b !important;
            padding: 36px 48px !important;
        }
        #header_wrapper h1 {
            font-family: "Helvetica Neue", Helvetica, Roboto, Arial, sans-serif !important;
            font-size: 24px !important;
            font-weight: 700 !important;
            color: #ffffff !important;
        }
        .td {
            color: #334155 !important;
            font-family: "Helvetica Neue", Helvetica, Roboto, Arial, sans-serif !important;
        }
        .shiv-order-notice {
            background-color: #f0fdf4;
            border: 1px solid #bbf7d0;
            color: #166534;
            padding: 12px 16px;
            border-radius: 6px;
            margin-bottom: 20px;
            font-size: 14px;
        }
    ';

    return $css . $custom_css;
}

This approach keeps your codebase clean, upgrade-safe, and light on maintenance overhead.

Method 2: Injecting Custom Content using Action Hooks

Suppose you want to add a custom banner, delivery instruction note, or social media link block inside the standard WooCommerce order email. Rather than duplicating template files, WooCommerce exposes strategic action hooks inside its email flow:

  • woocommerce_email_before_order_table
  • woocommerce_email_after_order_table
  • woocommerce_email_order_meta
  • woocommerce_email_customer_details

Here is an example where I inject a custom fulfillment status message specifically for the customer's processing order email:

/**
 * Add custom delivery note before order table in processing emails
 * Author: Shiv Parmar
 */
add_action( 'woocommerce_email_before_order_table', 'shiv_add_custom_email_notice', 20, 4 );
function shiv_add_custom_email_notice( $order, $sent_to_admin, $plain_text, $email ) {
    // Only execute on customer processing order emails
    if ( 'customer_processing_order' === $email->id ) {
        echo '<div class="shiv-order-notice">';
        echo '<p style="margin: 0;"><strong>Note from Our Rajkot Warehouse:</strong> Your order has been assigned to our packing team and will be dispatched within 24 business hours. You will receive a tracking link as soon as it ships!</p>';
        echo '</div>';
    }
}

By using hooks, your email layout stays intact even when WooCommerce updates its core email HTML structures in major releases.

Method 3: Overriding Template Files in Your Child Theme

When you need to perform deep layout adjustments—such as restructuring the entire HTML layout of the header, footer, or itemized table—template overriding is the correct path.

Step-by-Step Instructions:

  1. Navigate to your plugin directory: wp-content/plugins/woocommerce/templates/emails/
  2. Locate the template file you wish to modify (e.g., customer-completed-order.php).
  3. Copy that specific file into your active child theme using this directory path: wp-content/themes/your-child-theme/woocommerce/emails/customer-completed-order.php.
  4. Open the newly created file inside your theme directory and customize the markup safely.

Crucial Rule: Never modify WooCommerce core files directly inside the plugins/woocommerce directory! Any edits made there will be overwritten instantly when WooCommerce is updated.

Overriding the Email Header & Footer globally

If you want to create a completely custom email wrap (for instance, adding a sticky header navigation or a dynamic custom footer), override email-header.php and email-footer.php inside your-child-theme/woocommerce/emails/.

Testing and Previewing Custom Email Templates

One of the biggest pain points in WooCommerce email development is testing your changes. Placing test orders over and over to view design edits is extremely tedious and time-consuming.

To streamline this workflow, I recommend using these two development approaches:

  • Built-in WooCommerce Email Previewer: Navigate to WooCommerce > Settings > Emails in your WP Admin dashboard. Scroll down to the template customization settings and click "Click here to preview your email template."
  • Use Mailpit / Mailtrap on Local Environments: When developing locally (e.g., using LocalWP or DDEV), route outgoing emails through Mailtrap or Local's built-in Mailpit server to inspect exact inline styling and rendering behavior across various desktop and mobile clients.

My Personal Best Practice Recommendations

Throughout my years working on client e-commerce platforms, these core rules have saved me countless hours of debugging:

  1. Keep CSS Inline-Friendly: Old desktop mail clients (like Outlook) do not render modern CSS Grid or Flexbox well. Use standard HTML tables and inline block CSS properties for rock-solid cross-client compatibility.
  2. Favor Hooks Over Overrides: Before copying a template file into your theme, check if a WooCommerce hook exists that can achieve the same result. It reduces site maintenance significantly during major updates.
  3. Check Theme Overrides via Status Page: Always monitor WooCommerce > Status. If WooCommerce updates core email files, it will alert you if your theme overrides are outdated.
