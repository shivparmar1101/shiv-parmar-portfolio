    1. Core Web Vitals: Optimize Script Loading at the Theme Level

    Google’s Core Web Vitals directly impact your rankings. High Interaction to Next Paint (INP) or poor Largest Contentful Paint (LCP) times often stem from excessive script bloat. Instead of relying solely on heavy caching plugins, handle non-critical assets programmatically using native WordPress hooks.

    A. Defer Non-Essential JavaScript

    By default, WordPress enqueues scripts synchronously in the document head, blocking rendering. We can automatically append the defer attribute to scripts that are not critical for above-the-fold rendering.

    /**
 * Automatically defer scripts to improve Core Web Vitals (INP/LCP)
 * Author: Shiv Parmar
 */
function shiv_defer_parsing_of_js($tag, $handle, $src) {
    // Do not defer scripts in the WordPress admin panel
    if (is_admin()) {
        return $tag;
    }

    // List of handles to exclude from deferral (e.g., core jQuery)
    $excluded_handles = array('jquery-core', 'jquery-migrate');

    if (in_array($handle, $excluded_handles, true)) {
        return $tag;
    }

    return str_replace(' src', ' defer="defer" src', $tag);
}
add_filter('script_loader_tag', 'shiv_defer_parsing_of_js', 10, 3);

    B. Prevent Cumulative Layout Shift (CLS) via CSS

    Layout shifts destroy user experience and hurt technical scores. Ensure images and media elements have explicit aspect ratios in your global CSS reset:

    /* Prevent Cumulative Layout Shift for media elements */
img, iframe, video {
    max-width: 100%;
    height: auto;
    aspect-ratio: attr(width) / attr(height);
}

/* Reserve space for dynamic content blocks */
.ad-container, .hero-banner {
    min-height: 250px;
    contain-intrinsic-size: 250px;
    content-visibility: auto;
}

    2. Dynamic JSON-LD Structured Data Without Plugin Bloat

    Search engines rely heavily on Schema.org structured data to understand your content. Heavy plugins often output generic, bloated schema blocks. Injecting clean, custom JSON-LD directly into the document head via PHP gives you full control over precision and performance.

    /**
 * Inject Lightweight Custom JSON-LD Article Schema
 * Author: Shiv Parmar
 */
function shiv_add_custom_article_schema() {
    if (is_single() && get_post_type() === 'post') {
        global $post;

        $schema = array(
            '@context'      => 'https://schema.org',
            '@type'         => 'BlogPosting',
            'mainEntityOfPage' => array(
                '@type' => 'WebPage',
                '@id'   => get_permalink(),
            ),
            'headline'      => get_the_title(),
            'datePublished' => get_the_date('c'),
            'dateModified'  => get_the_modified_date('c'),
            'author'        => array(
                '@type' => 'Person',
                'name'  => get_the_author(),
            ),
            'publisher'     => array(
                '@type' => 'Organization',
                'name'  => get_bloginfo('name'),
                'logo'  => array(
                    '@type' => 'ImageObject',
                    'url'   => get_stylesheet_directory_uri() . '/assets/images/logo.png',
                ),
            ),
        );

        echo '<script type="application/ld+json">' . json_encode($schema, JSON_UNESCAPED_SLASHES | JSON_PRETTY_PRINT) . '</script>' . "\n";
    }
}
add_action('wp_head', 'shiv_add_custom_article_schema');

    3. Dynamic Robots.txt Management

    Managing crawl budgets is essential, especially for large e-commerce platforms built on WooCommerce. Instead of manually uploading physical robots.txt files, use the WordPress robots_txt filter hook to manipulate crawl directives programmatically.

    /**
 * Customize virtual robots.txt dynamically
 * Author: Shiv Parmar
 */
function shiv_custom_robots_directives($output, $public) {
    if ($public) {
        $output .= "Disallow: /wp-admin/\n";
        $output .= "Disallow: /author/\n";
        $output .= "Disallow: /?s=\n";
        $output .= "Disallow: /cart/\n";
        $output .= "Disallow: /checkout/\n";
        $output .= "Sitemap: " . esc_url(home_url('/sitemap.xml')) . "\n";
    }
    return $output;
}
add_filter('robots_txt', 'shiv_custom_robots_directives', 10, 2);

    4. Clean Up WordPress Header Clutter & Unused Assets

    WordPress outputs several legacy tags in the HTML header by default. These add extra byte weight and unnecessarily expose version numbers, creating potential security vulnerabilities alongside SEO bloat.

    Add these lines to your theme's functions.php file to strip out meta tags that offer zero value to search bots:

    /**
 * Clean up header bloat for clean DOM execution
 */
// Remove WordPress Generator Version
remove_action('wp_head', 'wp_generator');

// Remove Shortlinks (rel="shortlink")
remove_action('wp_head', 'wp_shortlink_wp_head', 10, 0);

// Remove RSD / EditURI Links
remove_action('wp_head', 'rsd_link');

// Remove WLW Manifest Links
remove_action('wp_head', 'wlwmanifest_link');

// Disable Block Library CSS on non-gutenberg templates (Optional tuning)
function shiv_remove_block_styles() {
    if (!is_singular('post')) {
        wp_dequeue_style('wp-block-library');
        wp_dequeue_style('wp-block-library-theme');
        wp_dequeue_style('wc-blocks-style'); // For WooCommerce sites
    }
}
add_action('wp_enqueue_scripts', 'shiv_remove_block_styles', 100);

    5. Essential Technical SEO Checklist Summary

    To keep your site at peak performance, follow this technical checklist whenever launching or auditing a WordPress project:

    1. Ensure Consistent Canonical URLs: Always enforce HTTPS, choose a single protocol structure (www vs non-www), and stick to strict trailing slash rules in Settings > Permalinks.
    2. Optimize Images Automatically: Serve modern formats like WebP or AVIF natively, and always explicitly define width and height attributes to preserve visual boundaries.
    3. Clean XML Sitemaps: Exclude low-value URLs such as tag archives, attachment pages, and private custom post types from your XML sitemaps.
    4. Audit Server Response Codes (HTTP Statuses): Use tools like Screaming Frog to clean up 404 broken links and eliminate unnecessary redirect chains (301 -> 301 -> 200).
    5. Database Maintenance: Clean post revisions, transient caches, and orphan meta data regularly to ensure fast SQL query execution times for search crawlers.
