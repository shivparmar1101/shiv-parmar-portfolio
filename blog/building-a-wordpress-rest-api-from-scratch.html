    While WordPress provides out-of-the-box endpoints for default posts, pages, and comments, real-world custom projects often demand custom data structures, higher performance, or specific business logic. In this post, I will walk you through building a custom WordPress REST API endpoint from scratch, complete with security checks, data sanitization, and frontend consumption.

    Why Build Custom REST API Endpoints?

    When building decoupled applications using React, Vue.js, or mobile apps that rely on WordPress as a backend, relying solely on standard endpoints can lead to inefficiencies. Custom endpoints offer several distinct advantages:

    • Reduced Payload: Fetch only the exact fields your frontend needs, avoiding over-fetching.
    • Enhanced Security: Hide internal WordPress metadata and establish custom authorization logic.
    • Aggregated Data: Combine data from multiple database tables or post types into a single HTTP request.
    • Custom Business Logic: Trigger complex server-side actions, such as sending emails or processing API integrations, directly via API calls.

    Step 1: Registering Your Custom REST API Route

    To create a custom endpoint, we hook into the rest_api_init action hook and use the register_rest_route() function. For this example, let us build an endpoint that returns a list of featured portfolio projects managed under a custom post type.

    Add the following code to your custom plugin file or your child theme's functions.php file:

    <?php
/**
 * Register custom REST API route
 * Author: Shiv Parmar
 */

add_action('rest_api_init', 'sp_register_portfolio_routes');

function sp_register_portfolio_routes() {
    register_rest_route('sp-api/v1', '/featured-projects', array(
        'methods'             => WP_REST_Server::READABLE, // Equivalent to 'GET'
        'callback'            => 'sp_get_featured_projects',
        'permission_callback' => 'sp_get_projects_permissions_check',
    ));
}

    Here is a breakdown of the key elements in register_rest_route():

    1. Namespace (sp-api/v1): Prevents route collisions. Versioning your endpoints is a crucial best practice.
    2. Route (/featured-projects): The URL endpoint appended to your WordPress REST API base URL (e.g., https://example.com/wp-json/sp-api/v1/featured-projects).
    3. Arguments Array: Specifies the HTTP method, the callback function that delivers the data, and the permission check handler.

    Step 2: Implementing Security and Permissions

    Security should never be an afterthought when developing endpoints. Even for public read-only routes, setting up an explicit permission_callback is mandatory in modern WordPress development.

    Key Insight: Never pass __return_true as a permission callback on endpoints that modify data or expose sensitive user information. Always validate user capabilities using current_user_can() or verify nonces to ensure your site remains secure against unauthorized mutations.

    Let us write our permission callback function:

    <?php
function sp_get_projects_permissions_check($request) {
    // For a public read endpoint, return true.
    // If restricted to logged-in users, use: return is_user_logged_in();
    return true;
}

    Step 3: Writing the Main Endpoint Callback

    The callback function is where your server-side logic resides. It executes the query, sanitizes the data, and wraps the output in a WP_REST_Response object.

    <?php
function sp_get_featured_projects($request) {
    $args = array(
        'post_type'      => 'portfolio',
        'posts_per_page' => 5,
        'post_status'    => 'publish',
        'meta_query'     => array(
            array(
                'key'     => '_is_featured',
                'value'   => '1',
                'compare' => '=',
            ),
        ),
    );

    $query = new WP_Query($args);
    $projects = array();

    if ($query->have_posts()) {
        while ($query->have_posts()) {
            $query->the_post();
            $post_id = get_the_ID();

            $projects[] = array(
                'id'        => $post_id,
                'title'     => get_the_title(),
                'permalink' => get_permalink(),
                'excerpt'   => get_the_excerpt(),
                'thumbnail' => get_the_post_thumbnail_url($post_id, 'medium'),
                'category'  => get_the_term_list($post_id, 'portfolio_category', '', ', '),
            );
        }
        wp_reset_postdata();
    }

    if (empty($projects)) {
        return new WP_REST_Response(array('message' => 'No featured projects found.'), 404);
    }

    return new WP_REST_Response($projects, 200);
}

    By returning an instance of WP_REST_Response, WordPress automatically converts your PHP array into a properly structured JSON object along with the appropriate HTTP status headers (200 OK or 404 Not Found).

    Step 4: Consuming the Endpoint with Frontend JavaScript

    Now that our endpoint is active, let us consume this data on the frontend using modern JavaScript. You can execute this script directly in your theme or enqueue it via a custom script file.

    document.addEventListener('DOMContentLoaded', () => {
    const container = document.getElementById('portfolio-container');

    if (!container) return;

    fetch('/wp-json/sp-api/v1/featured-projects')
        .then(response => {
            if (!response.ok) {
                throw new Error('Network response was not ok');
            }
            return response.json();
        })
        .then(data => {
            container.innerHTML = ''; // Clear loading state

            data.forEach(project => {
                const card = document.createElement('div');
                card.className = 'portfolio-card';
                card.innerHTML = `
                    <img src="${project.thumbnail || 'placeholder.jpg'}" alt="${project.title}" class="portfolio-img" />
                    <h3 class="portfolio-title">${project.title}</h3>
                    <p class="portfolio-excerpt">${project.excerpt}</p>
                    <a href="${project.permalink}" class="portfolio-link">View Project</a>
                `;
                container.appendChild(card);
            });
        })
        .catch(error => {
            console.error('Fetch error:', error);
            container.innerHTML = '<p>Failed to load projects.</p>';
        });
});

    Testing Your Endpoint

    Testing your API is straightforward. You can navigate directly to https://yourdomain.com/wp-json/sp-api/v1/featured-projects in your web browser or use tools like Postman or Insomnia. These API clients allow you to inspect HTTP response codes, headers, and payload structures effortlessly.
