1. Optimizing Largest Contentful Paint (LCP)

LCP measures how long it takes for the main content of a page—usually a featured image, hero banner, or large text block—to load. Target LCP time should be 2.5 seconds or less.

Step A: Preload Your LCP Image

By default, WordPress lazy-loads images. While lazy loading is great for off-screen images, applying it to your main banner or featured image delays its load time significantly. We should explicitly tell the browser to fetch the hero image immediately.

Add the following PHP snippet to your theme's functions.php file or a custom functionality plugin to preload the singular post featured image:

function shiv_preload_featured_image() {
    if ( is_singular() && has_post_thumbnail() ) {
        $image_id  = get_post_thumbnail_id();
        $image_src = wp_get_attachment_image_src( $image_id, 'full' );
        if ( $image_src ) {
            echo '<link rel="preload" as="image" href="' . esc_url( $image_src[0] ) . '" fetchpriority="high">' . "\n";
        }
    }
}
add_action( 'wp_head', 'shiv_preload_featured_image', 1 );

Step B: Exclude Hero Images from Lazy Loading

To stop WordPress from applying native lazy loading to your primary hero graphic, use the wp_get_attachment_image_attributes filter:

function shiv_optimize_hero_image_attributes( $attr, $attachment, $size ) {
    // Target the hero or featured image context
    if ( is_singular() && get_post_thumbnail_id() === $attachment->ID ) {
        $attr['loading']       = 'eager';
        $attr['fetchpriority'] = 'high';
    }
    return $attr;
}
add_filter( 'wp_get_attachment_image_attributes', 'shiv_optimize_hero_image_attributes', 10, 3 );

2. Mastering Interaction to Next Paint (INP)

In March 2024, Google officially replaced First Input Delay (FID) with Interaction to Next Paint (INP). INP measures overall page responsiveness by tracking the latency of all user interactions (mouse clicks, taps, key presses) throughout the lifespan of a page visit. An optimal INP score is 200 milliseconds or less.

High INP is usually caused by long JavaScript tasks locking up the main thread.

Step A: Defer Non-Essential JavaScript

Heavy JavaScript files, such as third-party analytics, chat widgets, or heavy plugin scripts, should be deferred so they do not block main-thread execution. You can automatically defer non-critical scripts via PHP:

function shiv_defer_non_critical_scripts( $tag, $handle, $src ) {
    // List handles of scripts to defer
    $defer_scripts = array( 'comment-reply', 'custom-analytics-js', 'contact-form-7' );

    if ( in_array( $handle, $defer_scripts, true ) ) {
        return str_replace( ' src=', ' defer="defer" src=', $tag );
    }

    return $tag;
}
add_filter( 'script_loader_tag', 'shiv_defer_non_critical_scripts', 10, 3 );

Step B: Break Up Long Tasks in JavaScript

If you write custom front-end JavaScript for your theme, avoid running long-running operations in a single block. Use requestIdleCallback() or yield control back to the main thread using setTimeout():

// Example: Yielding execution to keep UI responsive
function processHeavyData( items ) {
    let index = 0;

    function yieldAndProcess() {
        while ( index < items.length && performance.now() % 16 < 8 ) {
            // Do slice of work
            console.log( 'Processing item:', items[index] );
            index++;
        }

        if ( index < items.length ) {
            // Yield back to main thread
            setTimeout( yieldAndProcess, 0 );
        }
    }

    yieldAndProcess();
}

3. Eliminating Cumulative Layout Shift (CLS)

CLS measures visual stability. It quantifies how much unexpected layout shift occurs during the entire life cycle of the page. Target CLS score should be 0.1 or lower.

Common culprits include images without width/height attributes, late-loading web fonts, and dynamically inserted ads or embedded widgets.

Step A: Always Reserve Aspect Ratio Space for Images

Make sure every image in your CSS has an aspect ratio set or clear width and height attributes applied in HTML. Here is how I protect container layouts in CSS:

/* Standard Responsive Image Container Setup */
.post-thumbnail img {
    width: 100%;
    height: auto;
    aspect-ratio: 16 / 9;
    object-fit: cover;
}

/* Ads/Embed Placeholders */
.ad-slot-header {
    min-height: 90px;
    width: 100%;
    background-color: #f4f4f4; /* Reserve visual footprint before ad renders */
}

Step B: Prevent Font Flash with Font Display Swap

When custom web fonts load late, text elements shift when swapping from fallback system fonts. Add font-display: swap; to all your custom font definitions:

@font-face {
    font-family: 'CustomThemeFont';
    src: url('/wp-content/themes/my-theme/assets/fonts/custom-font.woff2') format('woff2');
    font-weight: 400;
    font-style: normal;
    font-display: swap; /* Keeps text visible using system font until loaded */
}

4. My Recommended Core Web Vitals Optimization Checklist

To keep things organized during client site audits here in Rajkot, I follow a systematic checklist:

  1. Hosting & PHP Version: Ensure the server runs PHP 8.1+ and uses modern protocols like HTTP/2 or HTTP/3.
  2. Object Caching: Enable Persistent Object Cache using Redis or Memcached to lighten database execution loads.
  3. Image Formats: Convert traditional JPEG/PNG formats to WebP or AVIF using automated tools or plugins like ShortPixel/EWWW.
  4. Asset Clean-up: Unload unnecessary CSS and JS assets on pages where they aren't used (e.g., dequeue form plugin styles on the homepage).
  5. Database Optimization: Regularly clean transients, post revisions, and spam comments using scheduled WP-Cron tasks.
