How to Create Custom WooCommerce Product Types

Hello fellow developers! I am Shiv Parmar, a dedicated WordPress and WooCommerce developer based in Rajkot, Gujarat, India. Over the years of building bespoke e-commerce solutions for clients around the globe, I have frequently encountered scenarios where standard WooCommerce product types just don't cut it. Out of the box, WooCommerce gives us Simple, Grouped, External/Affiliate, and Variable products. But what happens when a client asks for a rental system, a custom booking engine, or a subscription box with custom rules?

While you could hack simple products using custom meta fields, building a dedicated Custom Product Type in WooCommerce is the cleanest, most scalable solution. In this comprehensive guide, I will walk you through the process of creating a fully functional custom product type from scratch using clean PHP, JavaScript, and CSS.

Understanding How WooCommerce Handles Product Types

WooCommerce utilizes Object-Oriented Programming (OOP) to define products. Every product in WooCommerce inherits from the base WC_Product class or one of its extended classes (like WC_Product_Simple). When we create a custom product type, we simply extend one of these core classes, register the new type with the plugin's internal systems, and hook into the admin interface.

Key Insight: Creating a dedicated product type instead of cluttering simple products with custom meta fields keeps your codebase modular, preserves data integrity, and makes long-term plugin maintenance significantly easier.

Step 1: Registering the Custom Product Class

First, we need to create our custom class. For this tutorial, let us build a Rental Product type (rental). Create a custom plugin or use your child theme's functions.php file (a custom plugin is recommended) and define the class by extending WC_Product.

<?php
/**
 * Register custom WC_Product_Rental class
 */
add_action( 'init', 'sp_register_rental_product_type' );

function sp_register_rental_product_type() {
    class WC_Product_Rental extends WC_Product {
        
        public function __construct( $product ) {
            $this->product_type = 'rental';
            parent::__construct( $product );
        }

        public function get_type() {
            return 'rental';
        }
    }
}
?>

Notice how we set $this->product_type = 'rental' inside the constructor and return 'rental' in the get_type() method. This identifies our new class to WooCommerce.

Step 2: Adding the Product Type to the Admin Selector

Next, we need to make our new product type visible in the WooCommerce product data dropdown menu inside the WordPress dashboard. We do this by filtering product_type_selector.

<?php
add_filter( 'product_type_selector', 'sp_add_rental_product_type_selector' );

function sp_add_rental_product_type_selector( $types ) {
    $types['rental'] = __( 'Rental Product', 'shiv-parmar' );
    return $types;
}
?>

Step 3: Showing Relevant Data Tabs via JavaScript & CSS

When you select a product type in WooCommerce, JavaScript controls which data tabs (e.g., General, Inventory, Shipping) are displayed. By default, our new product type will hide standard pricing fields. We can fix this by injecting a small script into the admin footer to ensure fields like price and tax render properly when 'Rental Product' is selected.

<?php
add_action( 'admin_footer', 'sp_rental_product_custom_js' );

function sp_rental_product_custom_js() {
    if ( 'product' !== get_post_type() ) {
        return;
    }
    ?>
    <script type="text/javascript">
        jQuery( document ).ready( function( $ ) {
            // Add rental class to pricing and general options
            $( '.options_group.pricing' ).addClass( 'show_if_rental' );
            $( '.inventory_options' ).addClass( 'show_if_rental' );
            
            // Trigger WC type select change
            $( 'select#product-type' ).change( function() {
                if ( $( this ).val() === 'rental' ) {
                    $( '.show_if_rental' ).show();
                    $( '.show_if_simple' ).hide();
                }
            } ).change();
        });
    </script>
    <style>
        /* Custom admin style adjustments for rental type */
        #woocommerce-product-data ul.wc-tabs li.rental_options_node a::before {
            content: "\f310"; /* Dashicon for rental/calendar icon */
        }
    </style>
    <?php
}
?>

Step 4: Adding Custom Settings Panel & Data Fields

A custom product type often needs unique options. Let us add a custom tab called Rental Settings to hold specific options like Daily Security Deposit and Maximum Rental Period (Days).

<?php
// Add custom tab to WooCommerce product data meta box
add_filter( 'woocommerce_product_data_tabs', 'sp_add_rental_product_tab' );

function sp_add_rental_product_tab( $tabs ) {
    $tabs['rental_settings'] = array(
        'label'    => __( 'Rental Settings', 'shiv-parmar' ),
        'target'   => 'rental_product_data',
        'class'    => array( 'show_if_rental' ),
        'priority' => 21,
    );
    return $tabs;
}

// Render fields in custom tab panel
add_action( 'woocommerce_product_data_panels', 'sp_render_rental_product_tab_content' );

function sp_render_rental_product_tab_content() {
    ?>
    <div id="rental_product_data" class="panel woocommerce_options_panel hidden">
        <div class="options_group">
            <?php
            woocommerce_wp_text_input( array(
                'id'          => '_rental_security_deposit',
                'label'       => __( 'Security Deposit ($)', 'shiv-parmar' ),
                'placeholder' => '50.00',
                'desc_tip'    => 'true',
                'description' => __( 'Enter refundable security deposit amount.', 'shiv-parmar' ),
                'type'        => 'text',
            ) );

            woocommerce_wp_text_input( array(
                'id'          => '_rental_max_days',
                'label'       => __( 'Max Rental Duration (Days)', 'shiv-parmar' ),
                'placeholder' => '30',
                'type'        => 'number',
                'custom_attributes' => array(
                    'step' => '1',
                    'min'  => '1'
                )
            ) );
            ?>
        </div>
    </div>
    <?php
}
?>

Step 5: Saving Custom Field Data

Creating fields in the backend is only half the battle—we must persist this data when the product post is saved. WooCommerce provides action hooks specifically designed for product saves.

<?php
add_action( 'woocommerce_process_product_meta_rental', 'sp_save_rental_product_settings' );

function sp_save_rental_product_settings( $post_id ) {
    $security_deposit = isset( $_POST['_rental_security_deposit'] ) ? sanitize_text_field( $_POST['_rental_security_deposit'] ) : '';
    $max_days        = isset( $_POST['_rental_max_days'] ) ? sanitize_text_field( $_POST['_rental_max_days'] ) : '';

    update_post_meta( $post_id, '_rental_security_deposit', $security_deposit );
    update_post_meta( $post_id, '_rental_max_days', $max_days );
}
?>

Step 6: Handling Frontend Add-to-Cart Action

By default, WooCommerce will look for a template matching single-product/add-to-cart/rental.php when rendering the single product page for our custom type. If this file doesn't exist, the Add-to-Cart button won't render. You can link it to the simple product add-to-cart template or create a custom hook handler:

<?php
// Fallback to simple add-to-cart template if custom template does not exist
add_action( 'woocommerce_rental_add_to_cart', 'woocommerce_simple_add_to_cart', 30 );
?>

If you want custom frontend controls (like date pickers or rental duration inputs), you can attach a custom function directly to woocommerce_rental_add_to_cart instead of falling back to the simple product template!

Best Practices & Takeaways

When extending WooCommerce, always make sure to follow standard development practices to ensure compatibility across plugin updates:

  • Keep Code Modular: Group custom product types inside dedicated classes or plugin folders rather than stuffing everything in functions.php.
  • Use WooCommerce Helper Functions: Always utilize core functions like woocommerce_wp_text_input() and woocommerce_wp_select() for administrative controls to maintain visual UI alignment.
  • Sanitize and Validate: Never trust raw POST input. Use standard WordPress sanitization functions like sanitize_text_field() and absint() when saving post metadata.
